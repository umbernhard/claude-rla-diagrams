Risk-limiting audits from the ground up · Part 1: sampling

What can a few ballots tell you?

After an election, officials report a winner. An audit checks that report against the paper ballots. A full hand count of the paper is treated as representative of the outcome the voters chose, but it means reading every ballot, which is slow and expensive. A risk-limiting audit reads a random sample of ballots instead, and stops as soon as the sample makes a strong enough case.

New to audits? Start with why audits check paper ballots.

This page is about the first half of that idea: why a random handful of ballots can speak for the whole box, and what it can and can't say.

An election, drawn as a picture

Every example on this page uses the simplest contest there is: two candidates, Alice and Bob, and each voter votes for one of them. Real ballots usually list many contests, and some contests let voters choose more than one candidate, so a ballot and a vote aren't the same thing. Here we follow just this one contest, and every ballot has exactly one vote in it. When the counting is done, the result is two numbers: how many votes Alice got, and how many Bob got.

Two numbers make a point on a grid, so we can draw any result as a place: Alice's count across, Bob's count up. Counting builds the picture one ballot at a time. Each ballot with a vote for Alice is one step to the right, and each ballot with a vote for Bob is one step up.

Counting ten ballots

Ten voters cast ten ballots. Count them one by one and watch where the steps lead. The diagonal splits the grid in two: below it Alice has more votes, above it Bob does, and on it the election is tied. Every ten-ballot result lands on the dashed line where the two counts add up to ten.

There is no order of voting

Counting in a different order draws a different path, but every path ends at the same result. Ten ballots, six with a vote for Alice and four with a vote for Bob, can be put in 210 different orders, and here they all are at once.

Every order of the same ten ballots

Each one of these paths represents the same election outcome: 6 for Alice, 4 for Bob. Lines are thicker where more orders pass, and the number at each point counts how many of the 210 orders go through it. They all start at (0, 0) and all end at (6, 4). The steps toward Alice tend to be thicker because she got more votes: 126 of the 210 orders start with a vote for Alice and only 84 with a vote for Bob. At every point, the orders leaving it split in proportion to the votes for Alice and for Bob still left to count.

So which of these paths is the election? None of them in particular, or all of them at once. Every one ends at the same result, and nothing about the election picks one out. It's tempting to picture an audit as replaying the election ballot by ballot, in the order people voted. There is no such order. Two people can mark their ballots at the same moment. Ballots from different polling places are handled in different rooms, and mail ballots arrive over weeks.

None of that matters to the audit. Once the polls close, what's left is a pile of paper whose count no longer changes. The auditor creates an order by taking ballots out one at a time. Every sequence on this page is an order of taking ballots out, never an order of voting.

If the auditor counted every ballot, the order still wouldn't matter: every path ends at the same result. But the whole point of an audit like this is to avoid reading every ballot where possible. An auditor who stops partway sees only the start of one path, and the start of a path can be far from where it ends. So order does matter, but not in the way you might expect. The sequence itself doesn't carry any information. What matters is that the order decides which ballots the auditor has read by the time they stop, and the auditor treats those ballots as a fair sample of the whole box. If the box isn't mixed first, they may not be.

Reading a box that hasn't been mixed

This box holds 40 ballots: 22 with a vote for Alice and 18 with a vote for Bob. They are still stacked the way they arrived, one precinct after another, and the first precinct leaned toward Bob. Each ballot read moves the path one step: right for Alice, up for Bob. The blue arrow points at the full count.

Nothing read yet

Notice that the sequence itself was never the problem. Read those same first 12 ballots in any other order and the path ends at the same point, still leaning toward Bob. What went wrong is which ballots made it into the sample, and nothing in the sample warns you.

It's like a card game with a badly shuffled deck. Everyone at the table assumes the cards they're dealt are down to luck. If the deck wasn't really shuffled, the hands still look like ordinary hands, and nobody can tell from their own cards that someone has an advantage. An auditor works the same way: the math assumes the ballots read were a fair draw from the box.

Shuffling is what makes that assumption true, by giving every set of ballots the same chance of being the one read. Once the set is fair, the order within it doesn't matter: any path to the same point is the same sample, read differently.

Mix first, then draw

Humans are bad at randomness, so we need help to make sure we are really getting a good mix. Try it yourself.

Spot the real shuffle

Each row is 20 ballots, read one at a time from a box with as many votes for Alice as for Bob. Only one row came from a real shuffle. The other three were made up to look random. Which one is real?

The page generates the made-up rows to copy what studies find when people try to write down a random sequence: they switch between the two options more often than chance would, and they avoid long streaks.12 The real row is a fresh random draw each time, so now and then it looks tame too. Over a few sets, though, it usually has the longest streak.

To make sure we are really getting a good mix, we can use sources of "true" randomness, like rolling a fair die. However, if we had to sample every ballot that way, it would be really painful.

To deal with this, we use computers to help. But computers have the opposite problem from people: they're built to do exactly the same thing every time. Tap the camera icon on your phone and you get the camera, not a different app each time. Type 2 + 2 into a calculator and you get 4, today, tomorrow and next year. That predictability is what makes computers useful, and it's the opposite of random.

So computers use special programs called pseudo-random number generators (PRNGs), which give a new number every time you ask. Because the computer is still following fixed steps (that's the "pseudo" part), the numbers aren't really random; the generator fakes it. We help it out by giving it a kick from a truly random source, usually by rolling dice to "seed" the PRNG.

You've probably used one of these generators without knowing it: the shuffle button in a music app. It also shows how odd real randomness feels. In 2014, Spotify's engineers explained that listeners complained when a truly random shuffle played several songs by the same artist in a row, so Spotify changed shuffle to spread each artist's songs out. Their conclusion: "they don't like perfect randomness."3 That's the made-up rows from the figure above.

Two generators, side by side

Each box below feeds a seed to the same pseudo-random number generator. Type anything you like as a seed: a word, your name, a number. The generator turns it into a stream of numbers between 1 and 10, like the ones you picked above. It works by scrambling the seed together with a counter (1, 2, 3, …) and turning each scrambled result into a number. Once the seed is chosen, nothing is random.

Guess the next number

This generator has a secret seed. It will show you its numbers one at a time; before each one, guess what it will be. Without the seed, you have nothing to go on.

In a real audit, then, the shuffle happens on paper rather than by shaking a box. Election offices keep a list of where every ballot is stored, called a ballot manifest, and use the PRNG's numbers to pick ballots from that list. In Colorado, for example, the seed is a number of at least 20 digits, made at a public meeting after Election Day by rolling a ten-sided die once per digit, and members of the public are invited to do the rolling.4 Rhode Island's 2019 audit pilots did the same: observers rolled 20 ten-sided dice in public, which took about 14 minutes.5 The public part matters. If anyone could predict which ballots would be picked, a mistake or a tampered batch could be kept out of the sample. Because the seed is rolled in the open after the election, nobody could have known in advance where the auditor would look.

Know what you're drawing from

Every box on this page so far came with a known number of ballots. A real election doesn't. Its ballots are spread across hundreds of containers: boxes from each polling place, trays of mail ballots, bags of provisional ballots. Before an audit can draw a random ballot, someone has to know every container that exists and how many ballots are in each one. That list is the ballot manifest. Election offices build it from the records they keep as ballots are handled, not by counting every ballot again, but any entry can be checked by opening the container and counting.

A random sample is only random over the list it's drawn from. The dice and the generator pick numbers, and the manifest turns each number into a particular ballot in a particular container. A ballot that isn't on the list can never be picked, no matter what PRNG is used or what the initial seed was. Notice what the manifest doesn't record, too: it says where the ballots are, not how anyone voted.

From a manifest to a sample

Now the seed can do its job. Notice what the manifest above doesn't have: ballot numbers. Nobody writes a number on each ballot. The numbers are made up when the sample is drawn, by imagining every container on the manifest laid end to end, in the manifest's order, and counting along the line.

Number the ballots, then draw

Here is the same four-container election, counted and checked. Line the ballots up to give each one a number, then use the seed to draw.

Draw a few more and you may see several ballots in a row from the same container. That's normal. As the “Spot the real shuffle” figure showed, real randomness is streakier than it feels, and a generator that never repeated a container would be the suspicious one.

When the manifest is right, every ballot in the election has the same chance of being drawn. When it's wrong, that stops being true, and nothing in the sample itself will tell you.

To see why, take a traditional audit, the kind many states ran before risk-limiting audits: hand count a fixed percentage of the ballots, chosen at random. California's long-standing 1% manual tally, for example, hand counts every ballot from a randomly chosen 1% of precincts.6 The version below draws 10% of the ballots on the manifest, one at a time, to keep it small.

Two things follow. First, a ballot that the manifest lists but nobody can find can't simply be skipped. Careful audits treat it as the ballot most damaging to the reported outcome, so a missing ballot can only make the audit harder to pass, never easier.7 Second, the manifest has to be checked against records the voting system didn't produce: how many ballots are in each container, reconciled against how many voters checked in or had a mail ballot accepted.8 A manifest copied from the voting system's own totals can't catch the voting system's own mistakes. If a box is never scanned, like early voting box 2 above, the system's accounting won't flag it, because as far as the system knows, those ballots don't exist. Only independent information, like the voter check-in data, shows that ballots are unaccounted for. The same check also guards against deliberate changes to the system's totals.

Drawing ballots one at a time doesn't make a sample less fair than grabbing a handful at once. Fifty ballots drawn one by one are just as random as fifty drawn together. Reading them in sequence only lets the audit stop early, as soon as it has seen enough. That doesn't mean every audit stops at the first moment it could. Some jurisdictions deliberately draw more ballots than the math calls for: to make it very likely the audit finishes in a single round instead of going back for more, to meet other requirements in state law (such as a minimum number of ballots to check), or to make sure every county or town in the contest has some ballots to examine, so every local team gets practice. Extra ballots don't weaken the audit, as long as every ballot drawn gets examined and counted.

What a random sample looks like

How much is enough? Before an auditor can judge an unknown box from a sample, it helps to see what samples look like when we already know what's in the box.

Go back to the picture of every order of the same ballots. A fair shuffle makes each of those orders equally likely, so the share of paths passing through a point is the chance that a sample lands there. Counting paths is the same as working out chances. The next figure starts with a box small enough to count every path by hand. The one after it scales up to see the pattern that makes sampling work: a small sample can land almost anywhere, but the more ballots you read, the closer it sits to what's in the box.

A box of 100, shuffled 200 times

Turning the question around

So far we knew what was in the box and asked what a sample would look like. An auditor has the opposite problem: they hold a sample and want to know what's in the box. To keep things simple, imagine the whole election is a single box of 1,000 ballots. A real election spreads its ballots across many containers, but once they're listed on a manifest and numbered, drawing from them works just like drawing from one big box.

The same counting answers it, run backwards. Each possible result of the election is a different box: 600 votes for Alice and 400 for Bob, or 550 and 450, or a tie, and so on. For each of those possible boxes, ask: if the election really came out that way, how often would a random sample of the same size look like the one we're holding? If the answer is “often,” that result explains the sample well, and it stays in the running. If the answer is “almost never,” that result has a hard time explaining the sample, and it starts to look doubtful. A sample of 50 ballots with 32 votes for Alice, for example, is just what you'd expect from a box with 600 votes for Alice, but a box with only 200 would almost never produce it. Each possible result is checked on its own, so there's no need to guess beforehand which results were likely.

Here's a small example. Say the auditor draws 10 ballots and 8 of them have a vote for Alice. That sample suggests about 800 votes for Alice in the box. Now try some possible elections. If Alice received 600 votes, a random sample of 10 would have 8 or more votes for her about 17% of the time, roughly 1 time in 6. Nothing surprising there. If the election was a tie, it would happen about 5% of the time, a little more often than 1 time in 20. That's surprising, but not very. If Alice received only 300 votes, it would happen about 1 time in 670. That's very surprising. The other direction works the same way: if Alice received 980 votes, a sample of 10 would have 8 or fewer votes for her only about 1.6% of the time, because nearly every ballot in that box has a vote for her.

None of these numbers proves anything. A tie really could produce 8 votes for Alice out of 10; it just usually doesn't. Ruling an election out is a decision, not a proof: we agree to stop taking seriously any election that would rarely produce a sample like ours. The figure draws that line at 1 in 20. Wherever the line goes, it comes with a cost. If the true election is one of the unlucky ones, bad luck will sometimes rule it out, about as often as the line allows. A stricter line, like 1 in 100, makes that mistake less often but needs more ballots before it can rule anything out. Audits draw a line like this too, called the risk limit, and the next part comes back to it.

Which elections could have produced this sample?

This box holds 1,000 ballots. The reported result is 600 votes for Alice and 400 for Bob, but the auditor can't see inside. Each draw adds one ballot to the sample. For every election the box could hold, from 0 votes for Alice to 1,000, the curve shows how surprising this sample would be. The sample itself suggests a result: if 66 of 120 sampled ballots, or 55%, have a vote for Alice, the best single guess is that about 55% of the box, 550 of the 1,000 ballots, does too. For an election where Alice received fewer votes than that, “surprising” means how often a random sample of the same size would have at least as many votes for Alice as this one. For an election where she received more, it means how often a random sample would have this many or fewer. Where the curve falls below the dashed line, a sample like this would turn up less than 1 time in 20, so the figure shades that election as ruled out.

Too good for Alice keeps only the first half: it asks only whether an election could have produced this many votes for Alice or more, so it can only rule out elections that are worse for Alice. What's really in the box

Keep drawing and you may see an election get ruled out, then come back. That isn't a mistake in the figure. Each time the sample grows, the figure asks the question fresh, about the sample as it stands now. A short run of votes for Alice can push the tie below the line, and the next few ballots can lift it back up. Each snapshot is honest on its own. But imagine an auditor who checks after every ballot and stops the first time the tie is ruled out. Each check is another chance for a lucky run to push the tie below the line, and stopping early locks in whichever fluke comes first. If the election really was a tie, an auditor checking after each of the first 300 ballots would see it ruled out at some point about 1 time in 4, not 1 time in 20.

The result that matters

An audit doesn't need the exact count. It only needs to rule out the results in which the reported winner lost. The hardest of those to rule out is a tie, 500 to 500, because it sits closest to an Alice win. If an Alice-leaning sample would be rare from a tied box, it's rarer still from any box where Bob won. You can see this in the figure: left of its peak, the curve only rises, so once the tie drops below the line, every election Bob won is already below it. Making the case against the tie is enough.

That also means an audit can ignore the right side of the curve. An election even better for Alice than the sample suggests isn't a problem: Alice still won it. The Too good for Alice view keeps only the side that matters. It also changes how often the figure is wrong. With a 1-in-20 cutoff on each side, bad luck puts the true result in one of the shaded regions about 1 time in 10. But the mistake an audit has to guard against is confirming the wrong winner, and that can only happen on the left side. If Bob really won, a sample rules out every election Bob won at most 1 time in 20.

There are two natural ways to make that case. The first, in the “too good for Alice” view, asks only how surprising the sample would be if the election were tied. Flip a coin 100 times, get 60 heads, and you'll doubt the coin without doing any math. The second, in the “exactly this sample” view, also uses the reported result, and asks how much more often a 600–400 election would produce the sample than a tie would. Statisticians call that comparison a likelihood ratio. Both lead to valid audits.

One trap catches both, the one the figure showed: an audit that checks after every ballot gets many chances to be fooled, so it can't simply stop the first time the sample looks rare. The next part shows how ballot polling audits handle that.
